# إدارة مكتب المحاماة — برنامج محلي لويندوز وماك

برنامج سطح مكتب عربي (RTL) لإدارة مكتب محاماة وتوثيق واستشارات قانونية: العملاء والشركات، القضايا ومراحلها وجلساتها وأحكامها، المستندات (PDF وWord والصور) بنسخها، المذكرات، التحليل اليدوي، المهام والتقويم والتنبيهات، العقود والوكالات والأتعاب، قسم مستقل للاستشارات القانونية والاجتماعات (بمحاضرها ومهامها وماليتها)، التقارير بما فيها «التقرير الشامل للمكتب» (PDF وExcel)، والنسخ الاحتياطي والاستعادة — مع ربط اختياري للقراءة فقط مع أدوات الذكاء الاصطناعي عبر MCP.

- يعمل دون إنترنت ودون اشتراك أو حساب خارجي. لا تحليلات تتبع ولا اتصالات خفية (الواجهة تمنع أي طلب شبكة).
- البيانات في قاعدة SQLite وملفات فعلية على الجهاز داخل مسار بيانات المستخدم: `%APPDATA%\LawOfficeManager\data`.

**للمستخدم:** راجع `docs/دليل-الاستخدام.html` (يُفتح أيضًا من داخل البرنامج: الإعدادات ← حسابي ← فتح دليل الاستخدام).

## التثبيت

ملف التثبيت `LawOfficeManager-Setup-1.0.0-x64.exe` لويندوز 10/11 (64 بت). التثبيت للمستخدم الحالي دون صلاحيات مدير في `%LOCALAPPDATA%\Programs\LawOfficeManager`، مع اختصار «إدارة مكتب المحاماة» على سطح المكتب وقائمة ابدأ. إلغاء التثبيت لا يحذف البيانات. الملف **غير موقّع رقميًا** فقد يظهر تحذير SmartScreen («More info» ← «Run anyway»).

يُبنى ملف التثبيت ويُختبر تلقائيًا على ويندوز في GitHub Actions (`.github/workflows/law-office-windows.yml`): فحص الأنواع، اختبارات الوحدات والتكامل، التغليف، رحلة القبول الكاملة على البرنامج المغلف، ثم تثبيت صامت وفتح البرنامج المثبت وإلغاء التثبيت. يُرفع الملف الناتج كـ Artifact باسم `LawOfficeManager-Setup-x64`.

### ماك (macOS)

ملفات `LawOfficeManager-1.0.0-mac-arm64.dmg` (Apple Silicon) و`…-mac-x64.dmg` (Intel) تُبنى وتُختبر على أجهزة ماك آلية في GitHub Actions (`.github/workflows/law-office-macos.yml`): الاختبارات، التغليف، رحلتا القبول على التطبيق المغلف، ثم التثبيت من DMG في `~/Applications` وتشغيله وفحص مجلد البيانات وفتح المستندات بالبرامج الافتراضية.
- البيانات: `~/Library/Application Support/LawOfficeManager/data`.
- التوقيع: محلي (ad-hoc) فقط؛ **غير موقّع بهوية مطور Apple وغير موثّق (notarized)**. عند أول فتح يلزم «فتح على أي حال» من إعدادات النظام ← الخصوصية والأمن.
- SQLite مضمّن في Electron (`node:sqlite`) فلا توجد وحدة أصلية تحتاج إعادة بناء لكل معمارية.

## البنية التقنية

| الجزء | الاختيار |
|---|---|
| الإطار | Electron 44 (‏Node 24 مضمّن) + React 19 + TypeScript |
| قاعدة البيانات | SQLite عبر الوحدة المدمجة `node:sqlite` — لا وحدات أصلية تحتاج بناءً لكل نظام، فيعمل التغليف لويندوز x64 دون تعقيد التوافق. WAL + `synchronous=FULL` + مفاتيح خارجية + ترحيلات مرقمة + معاملات. |
| الحزم | esbuild للعملية الرئيسية وpreload وخادم MCP وعامل الاستخراج، وVite للواجهة. electron-builder (NSIS) للتثبيت. |
| الخط والأيقونات | IBM Plex Sans Arabic مضمّن محليًا (رخصة OFL في `dist/fonts/OFL-LICENSE.txt`)، وأيقونات Lucide مضمّنة. |
| PDF | pdf.js محلي للعرض (مع ملفات cmaps والخطوط القياسية)، وفي عامل منفصل لاستخراج النص للبحث. |
| Word | mammoth لمعاينة نصية تقريبية لـ DOCX واستخراج النص؛ الفتح الكامل ببرنامج Word المثبت. ملفات DOC تُحفظ وتُفتح خارجيًا دون معاينة. |
| الضغط | yazl/yauzl لحزم النسخ الاحتياطي. |
| MCP | ‏`@modelcontextprotocol/sdk` (خادم stdio، قراءة فقط). |

### الأمان

- `contextIsolation` و`sandbox` مفعّلان و`nodeIntegration` معطّل. الواجهة تُحمّل من بروتوكول `app://` محلي مع سياسة CSP صارمة، ويُلغى أي طلب http/https/ws.
- preload يتيح فقط استدعاء قنوات مسماة (`api:<domain>.<action>`)؛ كل قناة لها مخطط تحقق (zod) ومستوى صلاحية. لا SQL عام، ولا قراءة مسارات من الواجهة، ولا تشغيل أوامر. اختيار الملفات يتم بنوافذ النظام من العملية الرئيسية.
- الجلسة تُربط بالنافذة في العملية الرئيسية، ويُعاد تحميل المستخدم وصلاحياته من القاعدة في كل استدعاء؛ القفل بعد الخمول يُفرض هناك أيضًا. لا يمكن رفع الصلاحيات بتعديل الطلب (مُختبر باستدعاءات IPC مباشرة).
- كلمات المرور ورمز استعادة المالك مجزأة بـ scrypt (‏N=32768) من مكتبة التشفير المدمجة، مع إيقاف مؤقت بعد تكرار الخطأ.
- المرفقات: تحقق من الامتداد **ومن توقيع المحتوى**، حد 150 م.ب، نسخ إلى مجلد تجهيز ثم نقل ذري، بصمة SHA-256، اسم داخلي UUID، ومنع اجتياز المسارات. الفتح الخارجي يتم لنسخة اطلاع للقراءة فقط.
- **تسجيل الدخول لا يشفّر الملفات على القرص** — يُنصح بتشفير القرص (BitLocker).
- قفل يمنع فتح نسختين على البيانات نفسها (قفل Electron + ملف قفل في مجلد البيانات).

## هيكل المشروع

```
src/shared     ثوابت النطاق، مخططات التحقق، التواريخ (Asia/Riyadh)، التطبيع العربي، المبالغ بالهللة
src/main       العملية الرئيسية: core (المُرسل والجلسات)، db، services، ipc/registry، integration، extract
src/preload    الجسر المحدود
src/renderer   الواجهة: components، forms، pages، styles
src/mcp        خادم MCP للقراءة فقط
tests/unit     اختبارات Vitest للخدمات عبر المُرسل نفسه (علاقات، مالية، صلاحيات، حفظ، استعادة، تكامل)
tests/e2e      رحلة القبول الكاملة عبر الواجهة (Playwright + Electron)
docs           الدليل، صيغة التصدير، إعداد الربط، تقرير الاختبار
```

## الأوامر (للمطور فقط — لا يحتاجها المستخدم)

```
npm ci
npm run typecheck
node scripts/build.mjs          # بناء dist/
npm test                        # اختبارات الوحدات والتكامل
npm start                       # تشغيل نسخة التطوير
xvfb-run -a node --test tests/e2e/journey.e2e.mjs      # رحلة القبول (على لينكس دون شاشة)
xvfb-run -a node --test tests/e2e/appointments.e2e.mjs # الاستشارات والاجتماعات والتقرير الشامل
npx electron-builder --win nsis --x64                    # ملف تثبيت ويندوز (على ويندوز، أو لينكس مع Wine)
npx electron-builder --mac dmg --arm64                   # تطبيق ماك وملف DMG (على ماك فقط)
```

مساحة بيانات منفصلة للتجربة: `--data-dir=<مسار>` أو المتغير `LAWOFFICE_DATA_DIR` (يظهر شريط «مساحة بيانات منفصلة» في الواجهة).

## حدود معلنة

- الحسابات محلية على الجهاز الذي يحمل البيانات؛ لا مزامنة بين أجهزة.
- التنبيهات إشعارات ويندوز أثناء تشغيل البرنامج فقط؛ الفائت يظهر عند الفتح التالي. لا واتساب ولا اتصالات.
- لا ربط مع ناجز أو معين أو تراضي. لا تحويل هجري آلي ولا حساب لمواعيد الاعتراض.
- البحث لا يشمل الصور الممسوحة ضوئيًا (لا OCR).
- كشف الأتعاب ليس فاتورة ضريبية. لا تُسجَّل الضريبة في البرنامج، فلا يعرض التقرير الشامل مبالغ قبل الضريبة أو بعدها.
- تعارض المواعيد يُحسب للجلسة القضائية بمدة افتراضية (ساعة) لأن وقت نهايتها غير مسجل.
- ترقيم الصفحات وتاريخ الاستخراج في تذييل كل صفحة مضمونان في ملف PDF للتقرير الشامل؛ الطباعة المباشرة تعتمد على خيارات حوار الطابعة في ويندوز.
- الترقية من إصدار سابق تحفظ البيانات والمرفقات، وتأخذ تلقائيًا لقطة متسقة من قاعدة البيانات قبل ترقية بنيتها (`backups/auto/قبل-الترقية-*.sqlite`).
